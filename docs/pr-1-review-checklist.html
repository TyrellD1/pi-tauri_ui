Groups, run states & project picker

Human pass over what automation can't judge: hover timing, placement, wording, and cross-restart persistence. Work top to bottom; each box is one verifiable behavior.

Overall0 / 0
01

Run states

Pre-work: launch the dev app, open a project with at least two chats, start a slow turn (e.g. ask pi to explain the project).

While the turn runs, switch to another chat: the first row shows a grayscale spinner, not a blue dot. When the background turn settles, a blue dot appears on its row plus a “Finished in …” toast. Opening the dotted chat clears the dot (and the toast action jumps to it). Quit and reopen the app: finished-unseen dots are back; chats that were mid-run show no dot (their runs died with the quit). With prefers-reduced-motion on, the spinner is static (no rotation).
02

Custom groups

Pre-work: have 2+ chats in one project. The Groups parent sits above Projects.

Right-click a chat → hovering “Add to group ›” flies a submenu out to the right (no click needed); moving the mouse diagonally into it doesn't dismiss it. The submenu lists existing groups with ✓ on memberships; clicking toggles membership and the row appears/disappears in the group. “＋ New group” opens a naming modal; creating adds the chat and the new group accordion appears under Groups. Right-clicking a chat inside its group offers “Remove from …”; the hover × on a group header deletes the group but leaves the chats in their projects. The group header + starts a chat in that group's project, auto-adds it to the group, and shows a “project · group” notice. Collapse Groups and Projects, quit, reopen: both stay as you left them.
03

Context badges above the composer

Pre-work: open any chat (new or existing) and look just above the “Message pi…” input.

project · name and group · name pills sit left-aligned directly above the input on every chat, not just new ones. A chat in no group shows group · + Add; clicking it opens the membership menu (toggle ✓s plus “＋ New group”). Clicking the project pill opens the picker; picking a folder starts a fresh chat there and registers the folder as a project. The pills never overlap the queue bar, skill popup, or attach strip when those appear — transients stack above, pills hug the input.
04

Universal project picker

Pre-work: open the picker via a project pill or the + on the Projects header.

Clicking a folder descends into it; breadcrumbs jump back up to any level including /; going back is instant (cached, no spinner). Typing filters the current level within ~150ms; typing a path starting with / or ~ plus Enter jumps straight there. “Browse in Finder…” opens the native picker and the modal jumps to the chosen folder without closing. An unreadable folder shows an inline error and keeps the previous listing; Esc or Cancel closes without side effects. The primary button reads “Start chat here” from a badge and “Add project” from the Projects header, and does exactly that.
05

Recent

Pre-work: have chats across at least two projects with different ages.

Recent is the topmost parent, collapsed on first sight; opening it shows the 5 newest chats regardless of project or group, newest first. With 6+ chats, “Show N more” expands to 15 and “Show less” collapses back; reopening the app resets to 5. Recent rows behave identically to project rows: timestamps, run spinner, unseen dot, click-to-open, right-click menu. Sidebar search filters Recent like the other parents.
06

Queued messages survive chat switches

Pre-work: start a slow turn in chat A, queue a follow-up (“Queue” button), then switch to chat B.

Chat B shows no queue bar; switching back to A restores the exact queued text. If the run consumed the queue while you were away, returning to A shows “N queued messages were delivered while you were away” and the bar is truthfully empty. Quitting the app with a queued message loses it (processes die with the app) — acceptable, but confirm no stale bar claims otherwise on relaunch.
07

Skills popup

Pre-work: focus the composer in any chat.

Typing a bare / or $ shows nothing; typing one more letter reveals matching skills. No empty bordered box ever sits above the composer while typing normal text. ↑↓ / Enter / Tab / Esc / click all accept or dismiss as expected, inserting canonical /skill:name text.
